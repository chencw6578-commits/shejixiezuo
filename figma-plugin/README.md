# Figma 导出插件（设计协作）

把 Figma 里选中的画板直接导出到你的「设计协作」网站：在 Figma 选中画板 → 点上传，两步完成。
首选团队与项目后，插件会记住选择，下次打开自动带出。

## 上手

### 1. 在网站生成「导入令牌」

1. 打开网站，进入 **团队 → 团队设置**。
2. 选择作用范围：
   - **全部团队**（默认推荐）：插件里可以先选团队、再选项目；
   - **仅当前团队**：令牌只能导出到这一个团队。
3. 点 **生成导入令牌**，复制 `imp_` 开头的令牌。明文只显示这一次（服务端只保存哈希），丢了就重新生成。
4. 不用了随时点 **撤销**，插件再用会立即返回 401。

### 2. 安装插件

1. 打开 Figma 桌面端，菜单 **Plugins → Development → Import plugin from manifest…**。
2. 选择本仓库的 `figma-plugin/manifest.json`。
3. 之后在 **Plugins → Development → 设计协作 · 导出** 打开插件窗口。

### 3. 首次打开：粘贴令牌（之后就不用再填了）

第一次打开只有「粘贴导入令牌」一个输入框。粘贴第 1 步复制的 `imp_` 令牌，点 **保存并继续**。
令牌会被记住，下次打开直接进入主界面，**不需要重复粘贴**。v1.5.8 起令牌单独存一份（不再和偏好打包在一起），
并有四路存储互相兜底，任一路成功就能记住：

| 通道 | 位置 | 跨文件 | 仅本机可见 |
|---|---|---|---|
| `clientStorage` | 本机 Figma 插件存储（按插件 id） | 是 | 是 |
| 文档内 `pluginData` | 当前 Figma 文件 | 否 | 否 |
| 当前页 `pluginData` | 当前 Figma 文件 | 否 | 否 |
| iframe `localStorage` | 浏览器缓存（真实 Figma 里 origin=null，读取即抛错，仅作降级） | 否 | 否 |

- 网络失败、超时、CORS 或服务端 5xx：令牌**保留**，界面提示「连接失败（当前地址），令牌已保留」并提供 **重试**；
  若当前地址是本机而本机没跑后端，v1.5.6 起会自动改用线上服务重试一次；
- 只有服务端明确返回 **401 / 令牌已撤销** 时才会清空本地令牌并回到粘贴界面；
- 想换令牌：**高级设置** 里的「更改令牌」入口（不会每次打开强制出现）。

**每次打开都要重填？** 说明存储通道都没成功。插件会在粘贴页直接写出原因与修复办法：
Figma 对**没有固定插件 id 的开发插件**会禁用 `clientStorage`（官方已知行为），
把 `manifest.json` 加上插件 id 即可根治（只做一次）：

1. Figma 菜单 → **Plugins → Development → New plugin…**，随便起个名字；
2. 打开它生成的 `manifest.json`，复制里面的 `"id"` 值（形如 `1234567890123456789`）；
3. 把本仓库 `figma-plugin/manifest.json` 加上同一行 `"id": "…"`（上一行末尾要补逗号）；
4. 回到 **Plugins → Development** 重新 **Import plugin from manifest…** 选择本仓库的 manifest。

加完 id 后 `clientStorage` 可用，令牌跨文件、跨会话都能记住。v1.5.9 起 `manifest.json` **已内置固定插件 id**，正常导入后无需任何手工操作。

### 4. 日常使用：在 Figma 选中画板 → 点上传

- 中部列表是 **Figma 当前选中画板的只读镜像**：Figma 里选中哪些画板，这里就显示哪些，插件里不需要也不能勾选。
  在 Figma 里改变选中后会自动同步（旧版本 Figma 可重新运行插件刷新）。
- 没有选中任何画板时，列表会提示「请在 Figma 里选中要导出的画板」，底部按钮禁用。
- 顶部「导出到」显示当前的 **团队 / 项目 / 编组**。点 **更改** 才展开三个下拉：
  - 切换 **团队** 会自动清空并刷新项目；
  - 切换 **项目** 会自动刷新编组；
  - 编组可选「未分组」、已有编组，或 **+ 新建编组** 并填名称。
- 点底部 **导出并上传（N 个画板）**。进度条会显示读取节点 → 导出图片 → 上传，以及当前第几个画板；
  失败会在原地显示原因和 **重试**，不会跳新页面。
- 成功后显示「已导入 N 个画板 / M 个节点」和 **在网站中打开** 链接，可直接再传一次。

主界面常驻显示 **平台 / 倍率 / 位图切图 / 逐图层高清切图** 四项（在顶部目标条下方）：

- 平台决定查看器的逻辑单位：Android → dp、iOS → pt、Web → px；
- 倍率 1x / 2x / 3x 决定 PNG 切图清晰度，默认 Android/iOS 2x、Web 1x；
- **位图切图默认关闭**（只导结构最快，1229×883 这类大画板也只需几秒）；需要位图时再勾选，
  勾选后界面会提示「大画板导出切图较慢（单张最长 90 秒）」；单张超过 5MB 会自动跳过图片并提示，画板与节点仍正常导入；
- **逐图层高清切图默认开启**（v1.3.7）：带 Figma Export 标记的图层按元素本性导出——
  纯矢量元素出 **真矢量 SVG + 4x PNG**，位图元素出 **4x PNG**；网站端任意倍率导出优先从
  4x 源降采样、SVG 直接复用矢量，不再放大 1x 位图发糊。切片超过 5MB 或无 Export 标记时跳过并提示，
  切图上传失败只记告警，不影响画板导入（重试会补传，`/api/plugin/slices` 原位替换、幂等）。

**高级设置**（默认折叠）只保留服务器地址与「更改令牌」。

> 逐画板上传：位图体积大，插件一个画板一次请求，避免单次请求过大失败。
> 重复导入同一个 Figma 画板会**原位更新**，不会产生重复画板。

## 仅导出 JSON（离线备份）

底部次要入口 **仅导出 JSON** 会导出所选画板的 JSON，可复制或下载。
网站项目页的导入面板也支持粘贴这份 JSON（`POST /api/import/figma-json`）。

## 多上传目标配置（v1.8.0+）

一个插件可以保存**多套上传目标**，每套独立记住「服务器地址 + 导入令牌 + 团队 / 项目 / 编组」。
适合同一台电脑上有多个账号、或两个独立站点都要上传的场景：

- 插件顶部的 **上传目标** 下拉列出所有配置，格式是「配置名 · 域名」，选哪套就把稿子传到哪套对应的账号。
- **＋** 新建配置、**改名** 重命名、**删除** 当前配置（需二次确认；至少保留一套）。删除只影响本地配置，不动网站数据。
- 切换配置会重新连接对应站点并拉取团队列表，不会串到上一个账号。切换时若正在上传会被拦下。
- 每个账号的令牌在对应网站的「团队设置 → 导入令牌」分别生成；A 站令牌在 B 站无效（两套库互相独立），填错会 401。

**为什么不做「插件登录」**：插件界面运行在 `data:` iframe（origin=null），读不到任何网站的登录 cookie / localStorage；
真正决定上传目标的是「服务器地址 + 令牌」这一对，所以做成显式配置切换最可靠。网页上"两个域名都登录了"插件感知不到。

**升级兼容**：老安装（v1.7.0 及更早）原有的单份配置会自动迁移成第一套配置，令牌和目标保留，不影响已上传的稿。

## 服务器地址（默认连线上）

插件默认连接线上服务 `https://sjxz.yundongchangzu.com`，**开箱即用，不需要在本机跑后端**。
在浏览器打开 `https://sjxz.yundongchangzu.com/api/health`，看到 `{"ok":true,…}` 即表示服务正常。

### 双域名并存（v1.8.1+）

两套站点各自独立、可以同时用：新站 `https://sjxz.yundongchangzu.com`、旧站 `https://www.shilipix.cn`。
用顶部的「上传目标」为每套站点各建一个配置，每个配置分别填**自己站点**的服务器地址和令牌即可，切换下拉就能互传。
A 站令牌在 B 站无效（两套库互相独立），填错会 401；各站点令牌都在对应网站「团队设置 → 导入令牌」生成。

> **旧站请用带 www 的地址 `https://www.shilipix.cn`**，不要填裸域 `https://shilipix.cn`。Vercel 会把裸域 308 跳转到
> www，重定向响应不带 CORS 头，插件界面（data iframe，origin=null）里 fetch 会报「Failed to fetch」。v1.8.2 会自动把
> 裸域规范成 www（保留已填令牌），手动填裸域也会被纠正。

> v1.7.0 / v1.8.0 曾把旧域名配置**强制迁移**到新站并清空令牌，导致「旧站」配置错连新站、填旧令牌报 401。
> v1.8.1 已移除该强制迁移，并一次性还原被污染的配置、清空错配令牌；v1.8.2 修正还原目标为 www 域。
> 升级后请在旧站配置里重新粘贴旧站令牌、在新站配置里粘贴新站令牌；两个配置互不干扰。
> `shejixiezuo-gd7w.vercel.app` 仍属历史废弃地址（不再自动迁移，如仍在用请手动改地址）。

`manifest.json` 的 `allowedDomains: ["*"]` 已允许任意域名（Figma 官方 manifest 文档：`allowedDomains`
适用于已发布插件，`devAllowedDomains` 只是开发期的附加白名单）。因此**换地址不需要改 manifest**，
只要在插件「高级设置 → 服务器地址」填完整地址（带 `http://` 或 `https://`），点「重新连接」即可。
旧版文档里「换域名必须同步改 networkAccess」的说法已过时。修改插件文件后仍须重新
**Plugins → Development → Import plugin from manifest…**（或重启 Figma），开发插件不会热更新。

### 老安装自动回退（v1.5.6+）

v1.5.6 之前默认地址是 `http://localhost:4000`，老安装的偏好里可能还存着它。本机没跑后端时，
插件会**自动重试一次线上服务**并持久化新地址，界面提示「已自动改用线上服务」；401（令牌问题）不回退。
本地开发者要连本机：本机后端在跑时地址可用，不会触发回退；也可在「高级设置 → 服务器地址」
手动填回 `http://localhost:4000` 再点「重新连接」——用户主动改地址会重置回退标记。

服务端 `/api/plugin/*` 已对 `null`（Figma 沙箱 iframe 的 Origin）、`https://www.figma.com`、`https://figma.com`
与本地开发来源（`http://localhost:*` / `http://127.0.0.1:*`）开放跨域，并正确处理 `OPTIONS` 预检、允许 `Authorization` 头。
自建域名若不在白名单，需要改 `server/src/routes/plugin.ts` 里的 `pluginCors`。

## 常见问题

### 项目下拉是空的

插件会区分三种情况并给出不同文案：

- **该团队还没有项目，请先在网站创建**：数据问题，去网站项目页新建项目；
- **令牌无权访问该团队（权限问题）**：令牌是「仅当前团队」范围，换团队会被 403 拒绝；
  到网站团队设置重新生成「全部团队」范围的令牌；
- **未归属团队**：网站里早期未分配团队的项目会归到这里，只有「全部团队」令牌可见。

### 点了插件没反应

1. 确认 Figma 桌面端（浏览器版对开发插件支持有限）。
2. **Plugins → Development** 里应直接看到「设计协作 · 导出」条目；如果它变成了子菜单，
   说明 `manifest.json` 里误加了 `menu` 字段（本仓库没有）。
3. `manifest.json` 必须包含 `"documentAccess": "dynamic-page"`；缺了会在运行前加载整份文件，大文件看起来像没反应。
4. 修改插件文件后必须重新 **Import plugin from manifest…** 或重启 Figma，开发插件没有自动热更新。
   如果版本号已经是新版、界面却还在用旧文案（例如旧版才有的「主线程 10 秒」），说明 Figma 缓存了旧 `ui.html`：
   **完全退出 Figma 再打开**；v1.3.4 起插件会在版本不一致时弹出「插件界面是旧缓存」提示。

### 上传失败 / 401

- **401**：令牌填错或已在网站撤销 → 回团队设置重新生成并粘贴。
- **403**：令牌作用范围不允许访问该团队/项目 → 换「全部团队」范围的令牌，或改选令牌所属团队。
- **连不上服务器**：先看顶部常显的「已连接 / 未连接服务器」状态与地址。默认是线上服务
  `https://sjxz.yundongchangzu.com`；在浏览器打开它的 `/api/health`，能看到 `{"ok":true,…}` 就说明服务正常。
  老安装若还存着 `http://localhost:4000`，本机没跑后端时会自动回退到线上（v1.5.6+）。
- **域名 / TLS / CORS / mixed content**：请求没发出去时，错误文案会列出可能原因并附 `/api/health` 排查指引。
  `allowedDomains: ["*"]` 已允许任意域名，一般不必改 `manifest.json`（见上文「服务器地址」）。
- **「插件主线程 120 秒没有响应」／上传停在某个百分比（v1.5.7 已修）**：某些矢量节点的 SVG 导出会在
  Figma 原生层挂住不返回，期间主线程仍能应答 ping（诊断里写「主线程自报：仍在执行任务」），却发不出任何
  progress；旧版只看 progress 计时，120 秒后就把整板导出误杀。诊断里的 `POST /api/plugin/slices | HTTP 201`
  恰好说明服务端已经收下了切图，问题不在网络。v1.5.7 起单次导出带看门狗：SVG 20 秒 / 逐图层 PNG 45 秒 /
  整板位图 60 秒超时即跳过该格式（PNG@4x 保底），等待期间每 8 秒补发 progress 心跳，并熔断本轮后续 SVG；
  主线程自报 busy 时 pong 也计为心跳。v1.6.1 起取消「单次导出 5 分钟总时长硬上限」：只要还在发心跳
  就一直等到导完，不限时长；真卡死仍由 120 秒静默超时兜底。被跳过的 SVG 会写进成功页告警，画板与 PNG 切图照常入库。
- **长时间导出（十几分钟）属正常**：大稿/复杂矢量导出慢，v1.6.1 起不再按总时长掐断，耐心等进度走完即可；
  只有主线程彻底不发消息（诊断里 pong 也停）120 秒才会报「无响应」。若确实卡死，先关闭「位图切图」重试（只导结构），
  仍需要位图时降低倍率（3x → 2x）或拆分大画板，再用「重试」继续（已成功的画板不会重做）。
- **上传请求超时（60s），服务器无响应**：请求发出去了但 60 秒没回来，问题在服务端或网络链路；
  失败文案里会附一行 `诊断：[net] POST … | body=… | ERR/HTTP … | …ms`，把它发出来即可定位。
- **服务器返回 HTTP 401 / 403 / 5xx**：请求到达了服务端但被拒绝或出错，括号里是服务端返回的 error 文本。
- **位图超过 5MB**：降低倍率（3x → 2x）或关闭位图导出后重试。

### 每次打开插件都要重新粘贴令牌

先看粘贴页底部那行「原因 / 诊断」，它会直接说明是哪种情况：

- 显示「本地存储没生效：当前导入的 manifest 没带上插件 id」→ 重新 Import v1.5.9 的 `manifest.json`（已内置 id），或把 `id` 换成 Figma 分配的 id；
- ⚠️ 插件 id 不能改：clientStorage 按 id 隔离，id 一变，之前记住的令牌全部读不到（等于换了一个插件）；
- 显示「令牌没能保存」→ 三路存储都不可用，换台机器或换个 Figma 账号同样会失效；
- 显示「已读到上次保存的令牌（…）但校验未通过」→ 令牌已被网站撤销，重新生成再粘贴。

### 编组里看不到刚导出的画板

插件的编组属于项目里的「Figma 插件导入」设计稿；上传成功后编组下拉会自动刷新。
网页端手工建在其它设计稿下的编组不会出现在插件的编组下拉里。

## 数据与安全

- 令牌只在服务端存 sha256 哈希；明文仅在生成时返回一次，不写入日志、不写进前端构建产物。
- 插件把令牌、服务器地址、三级选择存在本机 Figma 插件存储（`figma.clientStorage`），
  必要时兜底写入当前 Figma 文件的 `pluginData`；不会发给第三方。
- 注意：写入文档内 `pluginData` 的令牌会随文件保存，**该文件的协作者理论上能读到插件数据**。
  在协作文件里使用建议补上 `manifest.json` 的插件 `id`，让令牌只留在本机。
- 位图切图按 `scale` 存为 PNG 资源，画板缩略图同步更新。

## 开发者备注

- `code.js`：主线程，读画板、导出 JSON（schemaVersion 1）、`figma.exportAsync` 导出 PNG（base64）、`figma.clientStorage` 偏好。
  心跳按阶段给静默上限：读节点 30 秒 / 单张切图 90 秒 / 单板上传 60 秒；切图每次导出前先发一条「第 N / M 张」进度；
  base64 每 256KB 一片（`image-chunk`）回传，UI 侧拼装后再上传；每步耗时同时打到 Figma 控制台（`[timing]`）。
- `ui.html`：单屏界面与所有网络请求（`fetch` + `Authorization: Bearer imp_…`）。
- 网站接口：
  - `GET /api/plugin/me` → 令牌所属团队与作用范围；
  - `GET /api/plugin/teams` → 可访问团队（id、name、项目数；「全部团队」令牌含 `unassigned` 未归属团队）；
  - `GET /api/plugin/teams/:teamId/projects` → 该团队项目（越权 403）；
  - `GET|POST /api/plugin/projects/:id/groups`、`POST /api/plugin/import`（越权 403）。
- 已用 Node `vm` 模拟 `figma` 对象验证主线程逻辑与请求体结构；**尚未在真实 Figma 客户端实测**（环境无 Figma 桌面端）。
- 文档依据：Figma Plugin API（`figma.showUI` / `figma.ui.postMessage` / `figma.exportAsync` / `figma.clientStorage` / `manifest.documentAccess`），核对日期 2026-11-08。
